# 守播 / NZ 系列

给县台直播源做的一套「扔在那儿没人管也能一直播」的播放器。跑在便宜电视盒子上，断流自己重连，卡住自己恢复，崩溃自己重启，停电来电自己起来。

三个项目同一套保活思路，互不干扰，能装在同一台盒子上共存。

## 怎么来的

最早只有 NZ 播放器（`nzp`），一个自愈型直播播放器。做完发现一个问题：山东融媒（litenews）把电视和广播拆成了两个 API 端点，`nzp` 的 `litenews://` 解析器只查电视那一个，**绝大多数县台的广播在里面根本取不到**（少数台把「综合广播」混在电视端点上，那是例外）。

于是在 `nzp` 上直接 fork 出 NZ 广播（`nzg`），解析器改成先查 radio 端点、没命中再回落 tv。包名换了，配置目录换了，端口也换了，所以两个 App 能在一台盒子上同时跑，各管各的。

再后来要在 PC 上听，就照 `nzg` 的频道清单写了 `nzg-win` —— 单个 exe，不装不依赖，Win7 起能跑。C 写的，静态链接，5.59 MB。

## 三个项目

| 目录 | 是什么 | 跑在哪 | 包名 / 产物 |
|---|---|---|---|
| `nzp/` | NZ 播放器 · 直播电视 | Android 电视盒子 | `com.shoubo.tv` |
| `nzg/` | NZ 广播 · 电台 | Android 电视盒子 | `com.shoubo.radio` |
| `nzg-win/` | NZ 广播 · Windows 版 | Win7 SP1 起 | `守播广播.exe` |

---

### nzp — NZ 播放器

自愈型直播播放器。开机自启，启动就恢复上次那个台；之后不再自动换台，只重连当前频道当前源。

- 内置 **117 个频道**，山东占 38 个，其余按县市分组；侧边栏分组 + 长按收藏 + 应用内加频道（m3u8 地址填进去就能看）
- 重连退避：立即 → 5s → 15s → 之后固定 30s 无限循环；网络恢复立刻重连，不等退避走完
- 看门狗 5 秒一轮：缓冲停滞 ≥10s，或者「显示在播但画面位置不动」≥15s，判死并重置
- 全局异常兜底，写日志后 3 秒重启；每天 04:00 主动自愈重建一次，防内存水位慢慢涨上去
- 日志按天切，留 7 天。所有应用内改动（加台、收藏、切台）写回 `/sdcard/守播/config.json`，换盒子拷配置就完成迁移

播放器是 ExoPlayer（Media3）。ijk 内核的配置字段留了，切换逻辑还没写。

### nzg — NZ 广播

从 `nzp` 整体 fork 过来，保活、远程同步、热加载这些能力全保留，只改广播化的部分。

- 内置 **28 个台**（山东 18 / 河南 3 / 安徽 3 / 内蒙古 3 / 广东 1）；台数随版本走，`build_nzg.py` 打出来的归档里能看到历史版本
- 唯一的逻辑改动在 `PlayerManager.kt`：`litenews://` 先查 radio 端点，没命中回落 tv
- 配置在 `/sdcard/NZ广播/`，服务端口 60081 —— 都是错开的，跟 `nzp` 装一起不打架
- 一键构建 + 版本归档：`python build_nzg.py v0.1.x_xx台_日期`，产物落在 `D:/ningz/nzg_versions/<标签>/`

差异全清单在 [`nzg/docs/NZG.md`](nzg/docs/NZG.md)，改动点、端口、路径、图标都列了。

### nzg-win — NZ 广播 Windows 版

同一个电台清单，搬到 Windows 上。单文件、绿色、双击就走。

| 项 | 值 |
|---|---|
| 体积 | 5.59 MB（单文件，静态链接，无外部 dll） |
| 机架 | PE i386，32 位；64 位 Win7/8/10/11 走 WoW64 一样能跑 |
| 依赖 | 只有 Win7 自带的 12 个系统 dll、357 个函数（用 msvcrt 不用 ucrt，ucrt 要 Win10） |
| 频道 | 72 个（山东 55 / 河南 6 / 广东 3 / 内蒙古 3 / 安徽 3 / 陕西 2） |
| 自检 | `--selftest` 72/72 通过，245 秒；`--selftest --live` 加活性判定，399 秒 |

启动后音量固定 100%，不记忆上次；`state.json` 只记停在哪个台、是否静音。会写一个
`HKCU\...\Run\ShouboRadioWin` 做开机自启，路径跟着 exe 走，不需要管理员。

源码在 `src/`（12 个 C 文件：`main` / `player` / `heal` / `resolve` / `ui` / `tray` / `config` / `json` / `liveness` / `util`），
`build.sh` 是构建脚本，`resource.c` 是打包进去的资源。

⚠️ **升级别只替换 `dist/`** —— exe 是放在版本归档目录里跑的，注册表自启项写的是那个目录的绝对路径。只换 `dist` 等于没升级，重启还是旧的（2026-10-23 就这么踩过一次，两个目录的日志混在一起，排查半天）。

## 踩过的坑

留档，省得下次再走一遍。

- **广播取不到**：不是源挂了，是 `litenews` 电视/广播两个端点，解析器只查了一个。这就是 `nzg` 存在的原因。
- **「在播」但画面冻着**：缓冲没停滞，播放器自己认为一切正常。看门狗得同时看缓冲和画面位置，只看缓冲会漏判。
- **升级了却还是旧版**：见上，`dist` 不是运行位置。
- **两个 App 抢端口**：nzp 60080 / nzg 60081，撞了远程配置就时好时坏。
- **内存慢慢涨**：单看一天没事，挂一周就掉。所以有每天 04:00 的定时重建，不是保险，是必需。

## 说明

频道源来自公开的融媒体直播地址，会失效、会换、会限流。内置清单只是「当时能用的那一版」，
不保证长期有效；能自己加频道就是为了这个。

代码是自己用的，没有对外 API 承诺，也不保证向后兼容。
